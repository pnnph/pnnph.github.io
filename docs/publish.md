# انتشار سایت روی GitHub Pages

یک‌بار انجام می‌شود؛ بعد از آن هر تغییری خودکار منتشر می‌شود.

نتیجه: `https://pnnph.github.io`

> **هشدار مهم:** هرگز پوشه‌ای به نام `maqzino-privacy` داخل این مخزن نساز. صفحهٔ حریم
> خصوصی مغزینو در مخزن جداگانهٔ `pnnph/maqzino-privacy` است و هر دو استور به آن آدرس
> لینک داده‌اند. پوشهٔ هم‌نام در این مخزن، آن صفحه را از کار می‌اندازد.

---

## آنچه آپلود می‌شود

**کدِ سایت**، نه خروجی ساخته‌شده. گیت‌هاب خودش می‌سازد و منتشر می‌کند.

این پوشه‌ها **نباید** آپلود شوند و حجمشان هزاران فایل است:

```
node_modules/    بسته‌های نصب‌شده — گیت‌هاب خودش نصبشان می‌کند
.next/           فایل‌های موقت ساخت
out/             خروجی ساخت
.preview/        عکس‌های آزمایشی
```

اسم این فایل‌ها در `.gitignore` هست، ولی **کشیدن و رها کردن پوشه در سایت گیت‌هاب،
`.gitignore` را نادیده می‌گیرد.** برای همین روش اول را پیشنهاد می‌کنم.

---

## روش پیشنهادی: GitHub Desktop

برنامهٔ رسمی خود گیت‌هاب. ورود با مرورگر انجام می‌شود، پس نه رمزی دست کسی می‌رسد و
نه با توکن سر و کار داری. `.gitignore` را هم درست رعایت می‌کند.

**۱. نصب و ورود**
از `desktop.github.com` نصب کن و با حساب `pnnph` وارد شو.

**۲. افزودن پروژه**
`File → Add local repository` و این مسیر را بده:
`D:\All My Web sites\A-Langing Page\pnnph.github.io`

چون این پوشه از قبل مخزن گیت است، بدون مشکل شناخته می‌شود.

**۳. انتشار**
دکمهٔ `Publish repository` را بزن و:

| گزینه | مقدار |
|---|---|
| Name | `pnnph.github.io` — **دقیقاً همین** |
| Keep this code private | ❌ تیکش را **بردار** (باید عمومی باشد) |

نام مخزن اتفاقی نیست: گیت‌هاب فقط مخزنی با نام `<username>.github.io` را روی آدرس
اصلی می‌نشاند.

**۴. روشن‌کردن انتشار خودکار**
در `github.com/pnnph/pnnph.github.io` برو به:

`Settings` → `Pages` → بخش `Build and deployment` → `Source` → **`GitHub Actions`**

(گزینهٔ پیش‌فرض `Deploy from a branch` است؛ حتماً عوضش کن، وگرنه گیت‌هاب کد خام را
سرو می‌کند به‌جای سایت ساخته‌شده.)

**۵. تماشای ساخت**
تب `Actions` را باز کن. یک کار به نام `Deploy site` در حال اجراست. دو سه دقیقه طول
می‌کشد. وقتی تیک سبز خورد، سایت بالاست.

## روش دوم: آپلود دستی

اگر GitHub Desktop را نخواستی. کمی دست‌وپاگیرتر است چون باید پوشه‌های سنگین را
خودت کنار بگذاری.

**۱. ساخت یک کپی تمیز.** در PowerShell:

```powershell
$src = "D:\All My Web sites\A-Langing Page\pnnph.github.io"
$dst = "$env:USERPROFILE\Desktop\upload-me"
robocopy $src $dst /E /XD node_modules .next out .preview .git .chrome-profile
```

**۲.** در `github.com` → `New repository` → نام `pnnph.github.io` → **Public** → بساز.

**۳.** در صفحهٔ مخزن، `uploading an existing file` را بزن و **محتویات** پوشهٔ
`upload-me` را بکش داخل (نه خود پوشه را). `Commit changes`.

**۴.** همان مرحلهٔ ۴ و ۵ بالا: `Settings → Pages → Source: GitHub Actions`.

## بعد از انتشار

**۱. از بیرون ایران بررسی کن.** به من بگو تا آدرس را باز کنم — درخواست من از خارج
می‌رود و معلوم می‌شود سایت برای همه باز می‌شود یا نه. (مهم است: بررسی‌کنندهٔ کافه‌بازار
و مایکت هم باید بتوانند بازش کنند.)

**۲. پیش‌نمایش لینک را امتحان کن.** آدرس را در تلگرام برای خودت بفرست؛ باید کارت با
نشان و اسمت ظاهر شود.

**۳. آدرس را جاهایی که باید بگذار:**
- پروفایل توسعه‌دهندهٔ کافه‌بازار (فیلد وب‌سایت خالی مانده)
- در اپ مغزینو: `AppConfig.kt` → `WEBSITE_URL` که فعلاً به صفحهٔ حریم خصوصی اشاره می‌کند

## از این به بعد، تغییر دادن سایت

هر تغییری که در کد بدهی و `Commit` و `Push` کنی، دو سه دقیقه بعد روی سایت است.
حتی می‌توانی متن‌ها را مستقیم در سایت گیت‌هاب ویرایش کنی: فایل `content/fa.ts` را باز
کن، مداد را بزن، جمله را عوض کن و `Commit` — سایت خودش دوباره ساخته می‌شود.

## وقتی دامنه خریدی

1. در `content/site.ts` مقدار `url` را به دامنهٔ جدید عوض کن.
2. فایلی به نام `CNAME` در پوشهٔ `public/` بساز که فقط یک خط باشد: دامنه بدون `https://`.
3. در تنظیمات دامنه، رکوردها را به گیت‌هاب اشاره بده (`Settings → Pages → Custom domain`
   خودش مقادیر را نشان می‌دهد).

هیچ لینک داخلی سایت دامنه را نمی‌شناسد، پس چیز دیگری عوض نمی‌شود.
